# 创意交互审查与 RISCV10 资源复核（2026-10-15）

审查对象为 PR #3 `fw/creative-interaction` 的 `ad2b345`，功能为 VC-02 语音切风格与 ESP32-S3 手机预览。原 PR 基于 RISCV08 的 `545f3b6`；本次保留 RISCV10 的 `ebcf01b` 优化，完成冲突处理和下列修复后重新构建。源码集成到 develop；main 保留已验收的历史发布，未将未上板的新功能宣布为实机通过。

## 修复的问题

- 原 ESP32 从 3030303 baud 的 UART1 TX 向 FPGA 115200 控制台发命令，实际无法可靠识别。现 UART1 GPIO18 只收视频；UART2 GPIO16 接 VC-02，GPIO17 向 FPGA 发控制命令，均为 115200。VC-02 RX 和 GPIO15 不接。
- 原 link 的 DRAIN 只倒计时，没有读取 FIFO。现恢复期间真正排空 FIFO，跨域禁止 tap 继续采集，等待稳定和 FIFO 空后退出，下一显示场重新开始，避免把残帧或半帧当新帧。也检查注册写请求被 FIFO 拒绝的情况。
- 原 MJPEG 调用了 WebServer 不存在的 `setContentType`，主机桩却声明了这个方法，掩盖编译错误。移除假接口；改为完整 HTTP 流响应，修正 multipart boundary，并把线上的小端 RGB565 转为 JPEG 转换器需要的大端顺序。
- 原解析器在 CRC 验证前修改尺寸，且只校验长度；错误尺寸可能导致 BMP 越界读取。现严格校验宽、高、格式和长度，仅在 CRC 成功后发布帧序号。网页、BMP、MJPEG 使用互斥保护的完整快照，避免接收缓存被并行覆盖。
- 可选 RISC-V 关键词模式调用 report/reload 时不再全程关闭中断；切风格复用 RISCV10 的扫描时间统计。默认仍关闭，原有固件 ROM 保持不变。
- 网页帧率按不同帧序号计数，避免把重复轮询同一图像算成新增预览帧。

## 资源与时序

Efinity 2026.1.132.4.5，Ti60F225 / I3，沿用 RISCV10 的 area 综合与时钟约束。interface、map、pnr、pgm 全部退出码 0。资源来自本次 place.rpt，时序来自最终 timing.rpt，而非中间 place.timing.rpt。

| 资源 | RISCV10 基线 | 集成后 | 新增 | 剩余 |
|---|---:|---:|---:|---:|
| XLR | 58284/60800 | 58940/60800（96.94%） | 656 | 1860 |
| RAM10 | 245/256 | 253/256（98.83%） | 8 | 3 |
| DSP | 145/160 | 145/160（90.63%） | 0 | 15 |

预览 FIFO 为 16bit × 4096，占 8 块 RAM10。本次功能资源足够，但仅剩 3 块 RAM10，不能再按旧 PR 的 254/256 或未优化工程的资源推断当前余量。

| 时钟关系 | 最终 setup slack | 最终 hold slack |
|---|---:|---:|
| 全局最小（两列可来自不同路径） | +0.288 ns | +0.026 ns |

最终报告列出的 17 组 setup、17 组 hold 关系全部为正。SDC 沿用基线，未新增时序豁免；原有无匹配 `vid_clk_dvi2`、`mode_key_n` 等历史告警仍存在。工具生成引脚表确认 stream_tx=GPIOL_01 / BGA R3、3.3V；BGA 球位不能直接当作排针编号，接线需核对板卡原理图。

## 验证与复现

- `python sim_stream.py`：小光栅、强制 FIFO 溢出恢复、1920×1080 光栅 148.5MHz / 100MHz / DIV=33 三组通过。真实尺寸收到三帧 96×54，每帧 5184 个像素及 CRC 全部一致，tap_drops=0、link_aborts=0；恢复用例强制一次溢出后收到九帧正确图像。
- `python wifi_stream/tools/check_host.py`：6/6，通过含/不含 JPEG 的 C++ 语法、字符语音模式、19 条真实语音匹配断言、真实 UART 初始化/帧解析器回归，以及独立 Python 协议参考。回归覆盖分段读取、坏 CRC、错误尺寸/格式/长度、序号回绕和快照复用。
- xPack GCC 13.4.0：RISCV10 基线与默认新源码二进制逐字节一致，12218 B，RAM 14528/16384 B。开启关键词模式编译通过，ROM 13530 B、RAM 15872/16384 B。此结论为同编译器源码对照；测试后已恢复原 fw_rom/ip ROM，没有替换受验收的镜像。
- `python build.py interface`、`map`、`pnr`、`pgm`：全部通过。非 ASCII 路径通过 STYLECAM_BUILD_DIR 指向独立 ASCII 构建目录；IVERILOG_BIN 指向本机 Icarus 的 bin 目录，GXX 指向主机 g++。
