# Resize、DDR、权重存储与推理引擎资源说明

本文对应已验收 RISCV11 AE / IN4 正式版。主工程仍使用 PE12 / 150MHz；未采用的资源试验不计入本次说明。

## 1. 工程有没有 Resize？

有，功能集成在 `StyleCam_camera/rtl/sc_camera_rgb.v`，不是名为 `resize.v` 的独立通用缩放器。

```text
SC431HAI 1920×1080 RAW10
  → 黑电平/通道增益、5×5 MHC 去马赛克、Gamma
  → 取中央1280×960视野
  → 每2×2 RGB像素块按颜色通道平均
  → 640×480 RGB
  → sc_capture按行水平镜像并写DDR
```

代码参数 `IW=1920, IH=1080, OW=640, OH=480`，裁剪左边界为 `(IW-2*OW)/2=320`，上边界为 `(IH-2*OH)/2=60`。理想图像坐标范围为横向320～1599、纵向60～1019；内部5×5窗口和流水计数带有对齐偏移，不能直接用它们的拍计数当原始坐标。

对R/G/B分别计算：

```text
out = (p00 + p01 + p10 + p11 + 2) >> 2
```

`+2`用于四舍五入。先求相邻两像素的水平和，把偶数行的和存入 `row_rgb`，奇数行到达时与上一行合并，得到2×2平均值。源端每拍四个RAW样本，输出接口每个有效拍可携带两个RGB像素。

这是**中心裁剪加固定两倍Box平均缩小**。不把整个16:9画面拉伸成4:3，也不是任意比例的双线性/Bicubic缩放。缩小在摄像头流中完成，仅需行存储，无须先在DDR保存一整张1080p图再调用软件Resize；RISC-V也不逐像素执行这一步。HDMI端把VGA结果放大显示是另一环节。

## 2. 网络权重到底存在哪里？

| 数据 | 持久保存 | 推理运行时的位置 |
|---|---|---|
| INT8卷积权重 | SPI Flash的模型blob，起始地址0x200000 | FPGA内部各层 `wram`，映射RAM10 |
| 量化/IN的M、B系数 | blob内有初始配置，运行中由IN逻辑刷新 | 各层片上系数RAM |
| 由gamma/beta/epsilon派生的IN定点常量 | 随设计的mem初始化文件 | FPGA片上常量ROM |
| 摄像头输入帧、推理结果帧及显示缓存 | 不要求掉电保存 | 外部DDR |
| 主要层间特征 | 不要求掉电保存 | 片上行缓存、FIFO和流水寄存器 |

正式版的权重路径是：

```text
SPI Flash → RISC-V校验模型CRC → 配置寄存器/配置口
          → 对应层的权重RAM → MAC阵列
```

`main.c`中的 `weights_load` 先校验完整blob，再由 `weights_pass` 逐条写 `SC_CFG_ADDR/LO/HI`。配置地址包含层号、分道和RAM地址。`mac.v`中 `wram` 的读口在计算时提供每拍需要的权重；主网络实例的 `WFILE` 为空，因此卷积权重依赖CPU装载，不是随BIT固定初始化。

所以准确说法是：**模型在Flash掉电保存，卷积权重加载到FPGA片上RAM后计算；DDR主要承担帧缓存，不是正式版卷积权重的逐拍来源。** 文中的DDR方案不能与独立V5通用引擎混用。

## 3. 参数这么少，为什么推理引擎资源仍然大？

参数量描述模型数值的数量；硬件资源还取决于并行度、每拍带宽、特征尺寸、端口数、缓存组织和控制逻辑。

正式版整体55,615 XLR、243块RAM10、145个DSP。层次报告估算整个推理引擎约33,642.5 XLR、150块RAM、141个DSP；其中网络约28,350.5 XLR、138块RAM，IN更新约4,432.5 XLR、12块RAM。引擎包含这些子模块，不能把父子层级重复相加。

### 实时计算需要并行硬件

本网络640×480单帧约339,148,800 MAC，30fps约10.17GMAC/s。13层采用专用流水模块，运算阶段在不同像素上重叠；末层PE12一次并行计算12个输出通道。乘法器、加法器、累加状态、通道选择和输出反压控制都消耗资源。三风格共享卷积权重，资源大不是因为同时算三份完整CNN。

### 权重RAM受每拍宽度限制，容量利用率不一定高

9,384个INT8卷积权重数值只有9,384B，但分散在不同层的独立RAM中，需要同时给各层MAC送数。

例如正式版末层每拍读取 `12×4×8=384bit` 权重，一行48B，深度36，总有效数据1,728B。综合映射需要约20块RAM10来提供该宽度，不能只按1,728B除以单块总容量来算块数。RAM还有固定宽深模式和端口约束，较浅的宽存储会浪费容量；这是以空间换带宽的实现代价。

### 中间特征与IN也消耗大量片上存储

推理引擎的150块RAM按当前层次报告可归为：

| 用途 | RAM10块数 |
|---|---:|
| 各层卷积权重 | 54 |
| 滑窗与行缓存 | 63 |
| 各层重量化/IN系数 | 13 |
| IN统计累加存储 | 5 |
| IN更新常量 | 12 |
| PixelShuffle奇数行缓存 | 3 |
| 合计 | **150** |

行缓存保存的是图像特征，不是训练参数；多层流水需要多组缓存。IN还需要均值/方差统计、较宽定点算术、系数更新和调度。引擎外的CPU、DDR控制器、摄像头、预处理和HDMI等另外消耗93块RAM。

把权重放DDR按需搬运，可以探索减少某些片上权重存储，但仍要安排计算侧权重缓存，并与视频帧读写竞争带宽；它不会自动消除MAC、行缓存和IN开销，也不能保证30fps。是否划算须由具体复用架构、带宽和实测决定。

## 4. 汇报时可直接使用的说法

> 我们采用中心裁剪和2×2平均实现1080p输入到VGA的流式Resize。模型在Flash保存，启动时由RISC-V校验并加载到FPGA内部权重RAM，DDR主要用于视频帧。模型参数虽少，但为了达到VGA约30fps，需要多层流水、并行MAC和高带宽权重读取，同时保留行缓存和动态IN，因此推理引擎占用较多逻辑、RAM和DSP。
