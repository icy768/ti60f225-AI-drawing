## 1. 确定采用的接线

子卡 QTE 座 J26 插到主板 J7，转出的 40 针排针叫 **J28**；配套图纸中 J26 / J28 同编号直通。
37 / 39 是排针编号，B3 / C3 是 FPGA 球位，不能混用。

| 起点 | 终点 | 用途 / 设置 |
|---|---|---|
| **VC-02-Kit TX1** | **ESP32 GPIO16** | 语音结果 → UART2 RX，115200 8N1 |
| **ESP32 GPIO17** | **子卡 J28-37** | 控制命令 → FPGA UART RX，115200 8N1 |
| **子卡 J28-39** | **ESP32 GPIO18** | FPGA 预览 → UART1 RX，3030303 8N1 |
| **子卡 J28-35 或 J28-36** | **ESP32 GND** | FPGA / ESP32 共地 |
| **VC-02-Kit GND** | **ESP32 GND** | 语音板 / ESP32 共地 |
| VC-02 MIC 接口 | 配套麦克风 | 按配套插头接入 |
| VC-02 SPK+ / SPK- | 配套 8Ω 2W 扬声器两端 | SPK- 不作为 GND |

VC-02 的 RX1、IOB8、3V3OUT、SDA/SCL 不接；ESP32 GPIO15 不接。
Kit 图是底视图，按实物 TX1 / GND 丝印找针。信号跳线尽量短，3Mbaud 预览先用约 10～15cm
的连接，并让地线靠近信号线；实际 CRC / 持续吞吐仍需板测。
两条 FPGA 信号均为 3.3V，**不需要电平转换模块**，不用改 J2/J3 的 MIPI Bank 电压选择。

## 2. 冲突核查：Efinity interface 已通过

把两处引脚变更放进隔离工程执行 Efinity Interface Designer，结果 **PASS**。
生成 pinout.csv 确认：

| 信号 | 主板 / 子卡 | GPIO / BGA | 方向 | Bank / 配置 |
|---|---|---|---|---|
| uart_rx | J7-37 / J28-37 | GPIOL_04 / B3 | Input | TL，3.3V LVCMOS，弱上拉 |
| stream_tx | J7-39 / J28-39 | GPIOL_06 / C3 | Output | TL，3.3V LVCMOS |

| 现有连接 | 核对结果 |
|---|---|
| 摄像头 MIPI | 当前 GPIOT_PN_06/07/09/10/11 属于 J4 摄像头链路，没有占新选 GPIOL_04/06 或 J7 子卡座 |
| 摄像头 I²C、DDR、HDMI、配置 Flash | 保持现有约束，新选两脚原先均未分配 |
| KEY3、复位 | GPIOL_03 / A3、GPIOL_07 / C4，与 B3 / C3 不同 |
| 板载 FTDI TX | 原 uart_rx 为 GPIOL_02 / R4；新输入移到 GPIOL_04，避免两个 TX 并接 |
| 板载串口日志 / JTAG | uart_tx 仍为 GPIOR_28 / R14，电脑仍可看 FPGA 日志，JTAG 下载不受影响 |
| 网口 PHY 复位 | 原 stream_tx 所占 GPIOL_01 / R3 不再发预览；报告显示该脚恢复输入 / 弱上拉，电路另有 R15 / 10k 上拉及 C33 |
| ESP32 USB / Flash / PSRAM | 用 GPIO16/17/18，不占原生 USB 的 GPIO19/20，也不使用模组 Flash / PSRAM 保留脚 |
| VC-02 UART | 模块 TX1 只驱动 ESP32 RX，RX1 留空，没有另一路 TX 并接 |

结论：**当前工程约束与 V4 电路上没有发现这套分配的冲突，接口工具检查通过**，仍未做实物验收。
证据在 `validation/v4_interaction_pincheck_20261020/`。

**当前正式 Flash 位流尚未使用新映射**：2026-10-21 已在独立候选中把 uart_rx 从 GPIOL_02 改到 GPIOL_04，
stream_tx 从 GPIOL_01 改到 GPIOL_06，并开启预览；完整构建及最终时序通过，需另按新包教程下载 RAM 候选。
这里只需重新分配已有端口，RISC-V 的 `0/1/2/v/s` 解析无需修改。
新映射下电脑 UART 的 TX 不再进入 CPU，控制从 ESP32 进入；电脑保留日志读取。
本轮没有覆盖主约束、正式位流或 Flash。

## 3. 供电按这个方案做

| 板卡 | 供电方式 |
|---|---|
| FPGA | **保持当前已验证的原配供电连接**，不从 ESP32 或子卡取电 |
| ESP32-S3 开发板 | **USB 5V**；调试接电脑数据 USB，脱机演示换稳定 USB 电源 |
| VC-02-Kit | **自身 USB 接 5V**；语音支路供电能力 >500mA，选 5V/1A 支路留余量 |

现阶段可用 **两根 USB 线分别接电脑供电足够的 USB 口**，不用另买电源模块或充电头；
VC-02 一路需满足 >500mA 的供电要求，优先使用电脑 USB 3.x 口。
脱离电脑时，才可改用现有充电头，或一只稳定的 **5V/2A 或更高总输出的双口 USB 充电头**，每口至少可提供 1A。
双口充电头只是可选供电来源，FPGA 继续独立用原配电源。2A 是电源容量，不是强行向板子灌入 2A。

```text
原配 FPGA 电源 ───────── FPGA
                          │ GND
5V USB 电源 ── USB ──── ESP32
                          │ GND
5V USB 电源 ── USB ──── VC-02
```

三板只把 GND 连在一起，**各板 5V / VCC / 3V3 不再相互并接**。
不用 J28 电源针脚给 ESP32 / 语音板供电，也不用 VC-02 3V3OUT 给其他板供电。
这样不用假定 FPGA 底板或 ESP32 底板的供电路径能额外承载另一块板。
烧录时，电脑 USB 替代该板的充电头 USB，同一块板不再额外并接 VCC / 5V 跳线。
供电是 5V，三条 UART 信号仍是 **3.3V 电平**。

## 6. 子卡到货前的调试

只接 VC-02 TX1 → ESP32 GPIO16、GND → GND，各自 USB 供电，GPIO17 / GPIO18 留空。
手机连 StyleCam（密码 stylecam1234），可用 `http://192.168.4.1/voice` 看原始语音字节。
电脑运行准备包中的 usb_control_bridge.py，可将 ESP32 的完整 `[cmd]` 日志转给 FPGA USB 控制台，
用于依赖电脑的控制调试，不传视频。串口号按实际设备替换，不能同时被监视器占用。
若板上仍是最近的 R14 新网络试验，先完成 TV51 / DDR 权重上传并进入 READY，再开桥接。
本轮没有切换 FPGA 板上的程序。
