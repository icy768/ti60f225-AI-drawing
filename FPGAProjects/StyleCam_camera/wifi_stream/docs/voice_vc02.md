# VC-02 离线语音模块配置与接入

本文只讲一件事：**把安信可 VC-02 配好、把它的串口输出对上固件**。
固件侧的解析逻辑在 `esp32s3_stream/`，映射表在 `esp32s3_stream/config.h`。

---

## 0. 先理解一件事：VC-02 没有"固定协议"

VC-02 是**离线**语音模块（安信可 Ai-Thinker，主芯片云知声蜂鸟 M / US516P6，
32bit RISC + DSP/FPU，最多 150 条本地指令，不用联网）。它在安信可语音开放平台上配置，
识别到命令词后从 UART 吐一串**你自己填的字节**。

这一点决定了整个接入方式：

> **每个命令词发什么字节，是你在平台上一条一条手填的**，默认模板 5 字节：
>
> ```
> [0] 0xA1 指令开头   [1] 设备位置   [2] 设备类型   [3] 开关状态   [4] 0xFF 结束
> ```

所以没有"VC-02 的协议"可以照抄，网上各种教程里的 `A5 00 00 FF 00`、`5A 00 00 00 01`
都是博主**自己填的**。

由此有两条等价的路，**二选一即可**：

| | 做法 | 什么时候用 |
|---|---|---|
| **A. 你定字节**（推荐） | 按本文 §1.3 把 5 字节填进平台即可——`config.h` 里的 `VOICE_RULES` 初值**就是这几个值**，一行代码都不用改 | 自己从头配这块模块 |
| **B. 先抓包再填表** | 说一句话，把串口打印的 `[voice] unmatched: ...` 粘进 `config.h` | 拿到的是别人烧好的模块、不知道里面填了什么 |

走 A 路的前提是**平台只发你填的那几个字节**；§3 的抓包就是用来**确认**这一点——
少数固件会自己加包头/包尾，真加了就得走 B 照实际字节改表。

配置平台：<http://voice.ai-thinker.com/>

## 1. 平台上要配的四件事

### 1.1 串口参数（最容易漏，漏了就一个字节都收不到）

| 项 | 值 | 说明 |
|---|---|---|
| 波特率 | **115200** | 与 `config.h` 的 `VOICE_BAUD` 必须一致；也是 UART1 的出厂默认（规格书） |
| 引脚 | **B6 = UART1_RX**，**B7 = UART1_TX** | Kit 排针丝印为 **RX1 / TX1**；B7/TX1 是模块往外发数据的脚，接 ESP32 的 RX |
| 数据格式 | 8N1 | 无校验 |

> 规格书确认：UART1 默认 115200 bps；UART0（IOB8 脚）默认 57600，是日志口，
> 别把它当识别结果口接线。

> **不要配置多个 UART1**，平台上多配一个 UART1 会导致 UART1 整个不工作。

### 1.2 唤醒词

2～4 个字，发音要有区分度（`小安小安`、`你好小安` 是出厂默认）。答辩现场环境嘈杂，
**别用 `你好` 这种容易误触发的词**。

### 1.3 命令词（建议词表）

每个命令词在"**控制详情 → 串口数据**"里填字节。建议沿用平台的 5 字节模板、
只改第 [2] 位当命令编号，这样以后看谁都能一眼读懂：

| 命令词 | 串口数据 | 映射到控制台 | 动作 |
|---|---|---|---|
| 梵高风格 | `A1 00 01 01 FF` | `0` | 风格 0 VAN GOGH |
| 浮世绘 | `A1 00 02 01 FF` | `1` | 风格 1 UKIYO-E |
| 水墨画 | `A1 00 03 01 FF` | `2` | 风格 2 INK WASH |
| 切换画面 | `A1 00 04 01 FF` | `v` | 循环切换布局 |
| 当前状态 | `A1 00 05 01 FF` | `s` | 打印 FPS / 风格 / 耗时 |

第三列就是 `config.h` 里 `VOICE_RULES` 的 `cmd` 字段——**是现有 RISC-V 串口控制台
已经支持的命令**（见 `stylecam/src/main.c`），所以 FPGA 侧一行不用改。

> 发音区分度很重要。`梵高风格` / `浮世绘` / `水墨画` 三个词的声母韵母差得远，
> 比 `风格一` / `风格二` / `风格三` 的识别率高得多——后者一定要避免，
> 语音模块最容易混的就是同韵母的编号词。

### 1.4 回复语（可选，但建议配）

每条命令词可以绑一句播报，比如"好的"、"已切换"。**尽量三五个字**：
播报期间麦克风会把自己播的声音收进去，回复语太长会导致连续重复识别。

## 2. 接线

Kit 排针丝印（左排自上而下）：SDA_5V / SCL_5V / SDA / SCL / IOA27 / **IOB8** /
**RX1** / **TX1** / GND / **VCC**；右排有 3V3OUT、DAC_L/R 等。
平台里的 `B6 = UART1_RX`、`B7 = UART1_TX` 对应排针上的 **RX1 / TX1**。

```
VC-02-Kit        ESP32-S3-N16R8            说明
TX1 (UART1_TX) ──► GPIO16 (UART2 RX)      模块发识别结果给 ESP32
RX1 (UART1_RX) ◄── GPIO15 (UART2 TX)      可选，ESP32 配置模块时用
VCC            ◄── 5V                      必须 5V 供电（见下）
GND            ──► GND                     必须共地
SPK+ / SPK-    ──► 8Ω 2W 扬声器            播报回复语用
```

- **供电是 5V，不是 3.3V**（规格书：VCC 4.5~5.3V，电流 >500mA）。板上自带
  5V→3.3V→1.2V 两级 LDO，排针上的 `3V3OUT` 是**输出**，别拿来当供电输入。
  直接从 ESP32 开发板的 5V 引脚取电即可。
- **IO 电平是 3.3V**，所以 TX1/RX1 与 ESP32 的 GPIO 直连，不需要电平转换。
- **别接 IOB8**：那是 UART0（默认 57600，日志口），不是识别结果口。
  识别结果只从 UART1（115200）出来。
- 语音模块识别瞬间电流会跳（典型 115mA，峰值 232mA），供电不足会重启
  （表现为反复播报欢迎语）。USB 串口线质量差时最常见。
- 扬声器功率不要贪大（官方建议 8Ω 2W）。
- 模块上电后有初始化时间并且会播报欢迎语，这段时间串口还没准备好，
  如果主控一上电就发配置指令会被丢掉。

## 3. 确认模块实际发的字节

- 走 **A 路**：这一步是**验收**——确认平台没给你加的字节偷偷塞包头/包尾。跑一次就够。
- 走 **B 路**：这一步**必须做**，因为表要靠它填。

### 方式一：串口日志

把 ESP32 用 USB 接电脑，打开串口监视器（115200）。对着模块说话，会看到：

```
[voice] unmatched: A1 00 01 01 FF   <- put this in VOICE_RULES (config.h)
```

这一行**就是可以直接粘贴的格式**——把它贴进 `config.h` 的 `VOICE_RULES` 即可。

匹配成功的会打印：

```
[voice] A1 00 01 01 FF -> console '0'
```

### 方式二：网页面板

手机连上 `StyleCam` 这个 WiFi，打开 `http://192.168.4.1/`，页面最下方有一个
**Voice module** 面板，勾选 "spy on the bytes the module sends" 后：
说一句话，刚收到的几帧字节就会实时列出来，新的一帧在最上面。

也可以直接看 JSON：`http://192.168.4.1/voice`

```json
{"mode":1,"rules":5,"bursts":12,"unknown":7,"last":"A1 00 01 01 FF",
 "captured":["A1 00 01 01 FF","A1 00 02 01 FF","..."]}
```

> 如果 `bursts` 一直是 0：**一个字节都没收到**。按顺序查——
> ① 波特率是否是 115200；② B7 是否真的接到了 GPIO16（TX↔RX 交叉）；
> ③ 平台上是否误配了多个 UART1；④ 是否共地。
>
> 如果 `unknown` 一直涨、`captured` 里有值：字节收到了，只是还没填进表里，
> 照着 `captured` 填 `VOICE_RULES` 就好。

## 4. 填进 `config.h`

```c
static const voiceRule_t VOICE_RULES[] = {
  { "A1 00 01 01 FF", '0' },   /* "梵高风格" -> style 0  VAN GOGH */
  { "A1 00 02 01 FF", '1' },   /* "浮世绘"   -> style 1  UKIYO-E  */
  { "A1 00 03 01 FF", '2' },   /* "水墨画"   -> style 2  INK WASH */
  { "A1 00 04 01 FF", 'v' },   /* "切换画面" -> cycle the layout  */
  { "A1 00 05 01 FF", 's' },   /* "当前状态" -> print status      */
};
```

语法：

- 空格分隔的十六进制字节，大小写都行；
- `??` 表示"这一位任意"——比如设备位置字节你不关心时写 `A1 ?? 02 ?? FF`；
- **长度必须完全一致**：`A1 00 01 01 FF` 只匹配 5 字节，收到 4 字节或 6 字节都不算命中。
  这是有意的——半截帧或前面混进杂字节时如果算命中，就会误切风格；
- 改完**不需要**动任何其它文件，重新编译烧录 ESP32 即可。

改完想确认表没写错，跑一次宿主机自测（不需要 ESP32 工具链）：

```bash
cd FPGAProjects/StyleCam_camera/wifi_stream
bash tools/check_host.sh
```

其中 `voice frame matching` 一项会把 `VOICE_RULES` **逐条**编译进去验证——
有拼错的字节、够不到的死规则都会在那里报出来。

## 5. 顺手可做：免唤醒词

平台支持**免唤醒命令**（最多 10 条），不用喊唤醒词直接说就能触发。

答辩演示时这个是加分项：观众不用知道唤醒词。但要注意免唤醒词一多，误触发概率上升。
建议只放**最可逆的那一个**：

| 免唤醒词 | 串口数据 | 效果 |
|---|---|---|
| 切换画面 | `A1 00 04 01 FF` | 直接切布局，不用先喊唤醒词 |

风格切换**不建议**设成免唤醒——误触发会在你没准备的时候把画面切走。

## 6. 与另一条路的关系

本文这套（模块 → ESP32 → FPGA 控制台）是 README 第 5 节的 **A 方案**，
**FPGA / RISC-V 固件零改动**。

如果不想经过 ESP32，可以把模块 TX 直接接 FPGA `uart_rx`，那就是 **B 方案**：
需要把 RISC-V 固件编上 `-DSTYLECAM_VOICE_TOKENS=1`，并让模块输出**英文单词**而不是
十六进制帧（`style0` / `ukiyo` / `next` …）。B 方案的词表见 README 第 5.B 节。

两条路都用 `uart_rx` 这一条线，所以**不要同时接**。
