## 唯一 frame_id 的统计口径

给每个真实 CSI 帧分配单调 source_id，随 DDR A 缓冲、NN、DDR B 缓冲、显示提交传播；不能仅在 NN 开始时重新编号。必须在摄像头 FIFO 之前统计物理源帧，才能发现前端损失。本包 `sim/frame_id_monitor.vh` 是仿真观测，不能自动在 FPGA 上读到；其中 `cam_go` 事件更不能替代真实 CSI 输入计数。

```text
timestamp_us,event,source_id,style,buffer_id,underflow,capture_drop,scheduler_skip
... ,csi_sof,       ...
... ,capture_done,  ...
... ,nn_start,      ...
... ,nn_done,       ...
... ,display_commit,...
```

有效推理 fps = 测试窗口内完成推理的不同 source_id 数 / 实际秒数。有效显示 fps 只计首次显示该 source_id；显示器每秒刷新60次不等于网络60fps。重复显示、采集丢帧、调度跳过必须分别记录。

现有 `a_latest` 调度偏向最新帧，可能跳过已采集但未推理的帧。30fps 连续输入而仅15fps处理，有限缓冲不能无限期做到“每个源帧都处理且不丢”。题目写有数据流不丢帧，团队必须对这一约束作真实设计取舍或向指导老师确认口径，不能把调度跳帧换个名字就宣称满足。

## 寄存器与单位

| 偏移 | 内容 | 注意事项 |
|---|---|---|
| 0x010 | CAM_FRAMES | 采集完成计数，非CSI源帧绝对真值 |
| 0x014 | NN_FRAMES | NN完成计数，仍需source_id验证是否处理重复帧 |
| 0x018 | NN_CYCLES | 单位是AXI时钟周期，不能按NN时钟换算 |
| 0x01C | DISP_FRAMES | 检查实际更新来源；不能单独证明新风格图帧率 |
| 0x038 | TIMER | AXI自由计数；用无符号差分处理32bit回绕，定期采样并展开时间轴 |
| 0x03C | UNDERFLOW | 显示欠载；跨域16bit计数不是完整系统无丢帧证明 |
| 0x008 | STYLE | 系数槽号，不是直接的风格号；每风格双槽 |
| 0x040–0x054 | IN控制/统计 | 测真实跨域读延迟，不能假定两次空读在任意时钟比下足够 |

`latency_ms = NN_CYCLES × 1000 / F_AXI`；普通计数 fps 的时间分母也必须用真实 `F_AXI`。硬件组同时返回仪器/独立计时结果，防止错误配置让屏幕显示虚高 fps。

## IN 与 ISP 重点

目前12个IN层轮换更新，不是每层每帧都用当帧统计。电脑合成曝光变化测试在24次刷新后才与同帧参考一致，途中有明显偏差；若每帧只更新一层且15fps，24帧约1.6s，这只是估算，实板可能更慢。风格bank切换延迟与画质稳定所需时间需分别测。

SC431HAI 分支使用固定初始曝光/增益、单位RGB增益，未套用旧传感器的AE/AWB；`raw_bin3`也没有`raw_bin2`的黑电平/gamma处理。应实测训练图RGB与实际摄像头RGB的亮度/色彩分布差异，在明确数据后调整ISP或相机域训练，不能把“图像尺寸正确”当成“图像域一致”。

IN均值、方差、平方根及系数计算目前落在RISC-V。除性能外，还需针对赛题“RISC-V仅高层控制、FPGA完成网络推理”核对合规性；若要求全部归一化计算在FPGA，需要另行实现统计到系数的硬件路径。

## 可选高阶720p挑战

另建真正1280×720输入/网络/缓存/输出配置，重新生成RTL、量化系数像素数表，检查行缓冲、像素数、每槽容量、总DDR、时序与帧ID。当前每槽2MiB小于720p的RGBA32帧3,686,400字节，不能只改NW/NH。卷积量约1.017G MAC/帧，30fps约30.523GMAC/s，不含其他开销。VGA放大到720p HDMI不算该挑战。
