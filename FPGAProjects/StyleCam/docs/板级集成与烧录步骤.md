# 板级集成与烧录步骤

## 1. 核对板卡与原厂摄像头通路

确认实际板卡型号、PCB 修订、Ti60F225 封装/速度等级、DDR 型号、MIPI 排线接法与电源、电平、下载器。只看到“Ti60”不能证明不同开发板管脚兼容。厂商资料中的历史 readme 也可能对应另一版参考板。

本包的 `vendor/sc431hai_camera_v6/ti60f225_oob.xml` 是厂商摄像头参考工程，带其 `.peri.xml/.sdc`。`vendor_camera_only_images/ti60f225_oob.bit/.hex` 保留原文件，来源为该演示原 outflow；未在本次重新构建，也未在实板验证。仅在与实际板卡和原厂工程版本匹配时，用它验证下载器、摄像头、DDR 和 HDMI。成功显示原图不代表 StyleCam 已烧录。

首次联调优先用 Programmer 的 JTAG 易失配置方式，文件格式以当前 Efinity Programmer 和板卡文档为准；保存器件扫描、IDCODE、下载日志及显示照片。Flash 固化应使用最终整合工程的地址布局及软件启动方式。本包不给未经核实的统一 Flash 偏移，不沿用 vendor 历史 readme 中的固件地址。

## 2. 组装完整板级工程

| 接口 | 本版约定 | 必须核实/补齐 |
|---|---|---|
| `vision_top` 摄像头入口 | `CAM_RAW=1`，1920×1440 RAW10，4 像素/拍，p0 在低 10 位 | CSI RX 的 RAW10 datatype=0x2B、valid 对齐、帧边界、4 lane、byte/pixel 时钟、物理针脚 |
| 缩小后 RGB | 640×480，RGB888；总线低字节 R | Bayer 相位、实际帧长、窗口、曝光/VTS/HTS、30fps，不能用 HDMI 刷新率代替 |
| `clk_axi` | 所有视觉 APB 寄存器和计时器的时钟 | 与实际 DDR 用户接口/桥一致；厂商参考存在 100MHz，而旧软件默认 150MHz，必须按实值修改 |
| `clk_nn` | 独立 NN 时钟，`NN_ASYNC=1` | PLL、复位同步、CDC，布局布线后真实 Fmax；不能只按目标频率计算 fps |
| 视觉 AXI | 128bit，32bit 地址，INCR burst | 与 SoC DDR 主口仲裁，ID/返回路由、背压、响应错误、地址转换；不可直接把两个主口并接 |
| APB | 视觉子系统 4KiB 寄存器窗 | 将其接入 Sapphire 用户 APB 从口；若不同时钟必须加正确桥接；确认 `VISION_BASE` |
| DDR 缓冲 | A×4 + B×3；每槽间距 0x200000 | 连续预留 14MiB，2MiB 对齐；与代码、堆、栈、bootloader 和其他 DMA 隔离 |
| HDMI | 当前 `vision_top` 1280×720 时序 | 74.25MHz 像素时钟、正确 TMDS 时钟比/极性/接口与引脚；神经网络仍为 VGA |
| SCCB/I2C | Sapphire I2C 调用，SC431HAI 默认 7bit 地址 0x30 | SID 实际接法、0xCD6B ID、电源/复位时序、ACK/timeout、上拉、总线归属 |
| 复位 | 多时钟复位入口 | 各 PLL lock、DDR ready 后再释放；摄像头启动前先确保帧缓存地址已设置 |

保留厂商 DDR/CSI/HDMI/IP 的正确外围约束，按真实顶层信号重新连接。`syn/vision_map.xml` 没有这些接口和时序约束，不能在它上面点 Generate Bitstream 作为整机交付。

仅编译一份 `stylenet_top.v`，必须来自 `rtl/gen/v21b_ukiyoe_qat900_640x480/`。加入全部配套 mem。通过本包脚本构建 ASCII 工作目录可修正 `$readmemh` 路径，避免“源码存在、初值没加载”的问题。

## 3. 构建匹配的 RISC-V 固件

将 `sw/main.c, vision.c, sc431hai.c, hal_sapphire.c` 和对应头文件加入实际 Sapphire standalone 应用。SC431HAI 路径不需要 `isp.c/removed_sensor.c`；它们保留作另一传感器参考，不能照搬 旧传感器 曝光/白平衡控制。

核对 `sw/board_profile.h`：

1. `VISION_BASE` 等于实际 BSP 导出的视觉 APB 地址。
2. `F_AXI` 等于视觉计时器真实频率，不是 CPU 或 NN 频率。
3. `STYLECAM_FRAME_BASE` 是视觉 AXI 所见、已独占预留的帧缓存起点。存在 AXI 地址转换时，不应直接照填 CPU 虚拟/逻辑地址。
4. 链接器给 RISC-V 程序/堆/栈的区域不覆盖整个 14MiB 帧缓存区。
5. 上述条件核对后，才设 `STYLECAM_BOARD_CONFIRMED=1`。

本版运行 `sqrt/ldexp/llround`，需链接数学库，并使用与生成 SoC 相符的 RISC-V ISA/ABI、启动文件和 linker script。当前电脑未发现可用的 RISC-V GCC，本次只完成主机 GCC 编译/运行检查，未输出可上板 ELF。Efinity RTL 软件安装完成不代表 Sapphire 软件工具链也已安装。

保留 ELF、map、bin/hex、编译命令和链接内存占用报告。`hal_sapphire.c` 当前 I2C helper 写后总是返回 0，主机测试不能证明硬件 ACK 检测；请结合真实 BSP 错误状态或寄存器回读补齐失败检测。

`main` 会检查视觉 ID `0x53544C31`、blob 长度和风格数、帧缓存基址回读以及传感器初始化；任一失败会停止 NN 启动。`STYLECAM_BOARD_CONFIRMED=0` 的停机是预期行为，不是烧录失败。源代码编译成功也不代表所填的地址有真实物理映射。

## 4. 完整 Efinity 构建

在真正的板级顶层完成外围生成、综合、布局布线、时序分析、bitstream 生成。确认无黑盒、缺失 mem、未连关键信号、危险时序例外；所有实际时钟和 CDC 有合理约束。保存完整 log/report，不仅截一个 PASS。

本次 v21 子系统 map 的 173 RAM10 / 125 DSP / 20,629 LUT / 14,388 FF 是视觉子系统综合结果，不含整合后的 Sapphire、DDR、CSI/HDMI/IP 总开销，不能当作整机资源充足的证明。

## 5. 上板调试与验收

按顺序通过：下载和串口 → DDR 测试 → 原图 RAW/RGB → 网络固定样本 → 三风格 → IN 刷新 → 帧 ID/帧率 → 切风格 → 连续运行。结果填写 [实测表](硬件组实测与回填.md)。

先把 `samples/input.png` 对应 RGB8 像素送入 NN，比较输出和逐层结果；不要把 JPEG 编解码后的像素直接拿来做 bit-exact 判定。CPU 的同帧 IN oracle 与实际轮换系数不是同一模式：固定系数应对 `exported_initial_banks` 测试向量，同帧系数要先按对应测试模式加载后再比较。

所有风格切换都应在一帧边界锁存 bank。先验证没有半帧使用新风格，再测切换延迟和稳态画质；本包小图切换仿真没有证明真实 VGA 运动场景的 <100ms 和无掉帧。

## 6. 电脑复验命令

以下从 `StyleCam` 根目录执行。Python 依赖见 `requirements_pc.txt`，RTL 工具需单独安装。所有 `--workdir/--stage` 指向尚不存在的 ASCII 目录，脚本拒绝覆盖已有结果。

```powershell
python -X utf8 tools/verify_delivery.py --workdir C:/fpga_check/v21_pc --gcc C:/mingw64/bin/gcc.exe
python -X utf8 tools/verify_delivery.py --workdir C:/fpga_check/v21_rtl --rtl --iverilog C:/iverilog/bin/iverilog.exe --vvp C:/iverilog/bin/vvp.exe --gcc C:/mingw64/bin/gcc.exe
```

完整 VGA 建议用已安装且支持 timing 的 Verilator + MinGW C++20：

```powershell
python -X utf8 tools/verify_delivery.py --workdir C:/fpga_check/v21_vga --rtl --vga --verilator --verilator-root C:/tools/verilator --compiler-bin C:/mingw64/bin --gcc C:/mingw64/bin/gcc.exe
```

本机验证使用 Verilator Python 分发 5.48.0，`VERILATOR_ROOT` 指向其含 `bin/verilator_bin.exe` 的根目录。安装布局不同时需调整对应启动工具；不要求硬件组复跑所有仿真才可开始板级集成。

```powershell
$env:PATH = 'C:/mingw64/bin;' + $env:PATH
python -X utf8 tools/check_camera_frontend.py --workdir C:/fpga_check/v21_raw --iverilog C:/iverilog/bin/iverilog.exe --vvp C:/iverilog/bin/vvp.exe
python -X utf8 tools/check_system.py --workdir C:/fpga_check/v21_sys --iverilog C:/iverilog/bin/iverilog.exe --vvp C:/iverilog/bin/vvp.exe
python -X utf8 tools/prepare_efinity_check.py --stage C:/fpga_check/v21_map
Set-Location C:/fpga_check/v21_map
& D:/bin/efx_run.bat vision_map.xml --prj --flow map --output_dir outflow --work_dir work_syn --timeout 300
```

最后一条的 `D:/bin` 是本机 Efinity 安装位置，其他电脑应换成自己的路径。此命令只重现子系统 map，不会生成完整板级 bitstream。
