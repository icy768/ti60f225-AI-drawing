## UART 诊断

每秒一行 `SCV1`，后跟10个32位十六进制数：

1. 25MHz参考累计周期。
2. 状态：bit0 模组释放、1 ID通过、2 配置回读通过、3 stream-on回读通过、4 序列结束；bit[7:5]错误码（2=NACK、3=值不符、4=超时）；[15:8]命令索引；16 DDR校准完成、17像素快照新鲜、18字节时钟快照新鲜。
3. 完整好帧累计数。
4. 坏帧累计数。
5. 最近完整帧RAW像素数，期望2073600。
6. 最近有效载荷格式：VC[27:26]、datatype[25:20]、PPC[19:16]、word_count[15:0]；期望0 / 0x2B / 4 / 2400。
7. 最近相邻帧开始的50MHz周期数，换算实际摄像头帧率。
8. 同步后的CSI IRQ上升沿累计数；未核全部中断屏蔽，不能当作完整CRC/ECC验收。
9. 最近帧RAW高8位载荷的32位累加校验值，可辅助检查内容变化。
10. MIPI恢复字节时钟累计周期，与参考时间差分得到平均活动率；不是对瞬时HS频率的独立测量。

快照使用请求/应答和保持稳定的数据总线；ACK再同步3拍后取数。源时钟停止会保持请求pending，不会因反复翻转请求伪造成功。串口最多等待10ms，即使没有摄像头时钟也持续报告；新鲜标志无效时不能使用旧数值证明当前收帧。统计不阻塞视频。

配置结束额外发送一次 `SCE1`：第一个32位字段是参考周期，其余9个字段各为 `00 + 16位寄存器地址 + 8位实际读数`，顺序为3E00/01/02、320E/F、3E08/09、3E06/07。这些是只读诊断，未知默认值不作强制比较；I²C失败不生成有效完整读数。SCE1、SCV1、RAW1、ROI1由串口仲裁保证整条记录不交错；解析时均排除本次启动前残留，双路数据按各自标记分开校验288条记录，不相互拼接。曝光/帧长解析保存在实板目录的 `sensor_registers.json`。
