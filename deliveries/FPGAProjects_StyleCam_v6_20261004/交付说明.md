# StyleCam v6 硬件组交付说明

交付日期：2026-10-04。目录结构保留 `FPGAProjects/StyleCam` 的形式。本包是独立副本，原始工程及其旧部署权重未覆盖。

## 先读结论

**本包可以交给硬件组进行板级集成与联调，但还不能直接烧录出三风格视频系统。** 最新 v6 已补齐实际整数导出、RTL 逐层对拍、固件主机检查和 Efinity 子系统综合。当前缺少接好真实 MIPI、DDR、Sapphire、HDMI 并通过布局布线时序检查的完整 StyleCam 板级 bitstream，也没有与其匹配并完成交叉链接的 RISC-V 固件 ELF。

`StyleCam/vendor_camera_only_images/` 中的 `.bit/.hex` 是原厂摄像头演示文件，**不包含 v6 网络**。`net_blob.bin` 是网络寄存器加载数据，**不是 FPGA 烧录文件**。不要把任意旧 bitstream 与本包新 blob 混用。

## 模型与配套关系

- C24/Fc16，4 个 `dw1` 残差块，13 层卷积；640×480 输入输出；共享卷积，三组条件 IN 参数。
- 风格 0：`van_gogh`；风格 1：`ukiyo_e`；风格 2：`ink_landscape`。每个风格占两个 IN bank：0/1、2/3、4/5。
- 参数 11,028 个；卷积 MAC 339,148,800/帧，不含 IN、访存、预处理、显示与控制开销。
- blob 48,616 字节，4,050 次 cfg 写入。其小于 500 KB 不等于完整程序、视频缓存及 FPGA bitstream 小于 500 KB。
- 本版是 **FP32 v6 + 100 张图激活校准 + INT8 PTQ**，没有把旧 QAT 成绩移到新模型名下。导出初始 IN 系数使用 32 张训练侧图片，R/S 标定使用其中 4 张；与 100 张激活范围校准是两个步骤。
- 卷积参数、量程、R/S、初始 IN bank、`stylenet_top.v`、`sw/net_blob.h`、`sw/in_params.h` 必须整体使用。只更换 `.pt` 或 blob 不会自动更新 RTL 常量。

## 本次修补与仍需解决的内容

交付副本默认 `CAM_RAW=1, IW=1920, IH=1440`，固件调用 SC431HAI 驱动；屏蔽 IMX219 专用 AE/AWB/翻转/测试图命令。此 SC431HAI 模式的物理帧率、Bayer 相位和 MIPI 参数仍需实测，现有驱动对厂商表的 1920×1440 改动不能视为已验证传感器模式。

固件加入 blob 格式/风格数/长度校验、加载失败停止启动、摄像头初始化失败停止启动，以及帧缓存基址设置和回读。`board_profile.h` 默认 `STYLECAM_BOARD_CONFIRMED=0`，因此未确认配置的程序会在串口提示后停止访问视觉 APB。请先核对实际 `VISION_BASE`、`F_AXI`、`STYLECAM_FRAME_BASE`，保留 7×2 MiB 独占 DDR 空间并检查链接地址，再将该开关设为 1。不要只改开关而保留未经核对的默认地址。

硬件组还需要完成完整 SoC+DDR+视觉子系统仲裁、真实接口与约束、固件交叉编译/链接、板端唯一帧 ID 观测。IN 的均值/方差/平方根及系数更新目前在 RISC-V，FPGA 负责累积统计和仿射运算；这项分工需要针对题目的“RISC-V 仅做高层控制”要求进一步核对或改为硬件实现。

## 本次不能作出的承诺

RTL 与整数参考一致，不能证明真实传感器稳定、DDR 无阻塞、整机持续超过 15fps，或风格切换小于 100ms。动态同帧 IN 的参考图也不是当前固件逐层滞后刷新下每一帧的保证。模拟曝光变化中观察到明显过渡偏差，见 PC 报告。

本包附的是当前画质候选，艺术特征和整数损失仍需人工验收。后续优化应以本包整数图和真实 RAW/RGB 视频为准，不能仅用原始 FP32 图作比赛效果承诺。

## 收到包后的第一步

在解压根目录执行：

```powershell
python -X utf8 StyleCam/tools/check_manifest.py
```

随后阅读板级集成文档。建议把工程工作副本放在如 `C:/fpga_work/StyleCam_v6/` 的纯英文目录。包中不含 Python 虚拟环境、Efinity 安装包/许可证、完整 COCO 数据集或庞大综合缓存。验证所需的小样本和参考输出已经包含；完整重新训练仍需恢复训练数据集。
