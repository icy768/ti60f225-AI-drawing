# 外部 Fast Neural Style 项目与 StyleCam v6 对照审查

审查日期：2026-10-05

## 审查对象

用户提供的博客介绍的是 `hzy46/fast-neural-style-tensorflow`。博客明确描述了生成网络、VGG 损失网络、InstanceNorm、5 个残差块以及训练/执行分离；仓库 README 使用 COCO train2014、VGG16 和每种风格单独配置训练。该仓库的源代码快照、提交号、SHA256 和卷积量核算保存在 `audits/external_fns_hzy46_20261005/audit.json`。

## 是否与 v6 相同

不是同一个 baseline。两者属于同一类 Johnson/Fast Neural Style 方法，但部署图不同。

| 项目 | 外部 Fast Neural Style | StyleCam v6 |
|---|---:|---:|
| 训练/推理框架 | TensorFlow 1.x 风格实现 | PyTorch 训练 + 自有整数 golden/RTL 接口 |
| 风格组织 | 每个风格一个 checkpoint | 一个共享卷积图，3 个条件 IN 风格行 |
| 主干 | 32/64/128 普通卷积，5 个普通残差块 | C=24、Fc=16、4 个 dw1 残差块 |
| 大卷积 | 首尾 9×9 | 当前图无外部 9×9 结构 |
| 参数量 | 1,674,432 个卷积权重，FP32 约 6.68 MB | 11,028 个总参数 |
| 640×480 卷积 MAC | 50,751,360,000 | 339,148,800 |
| 量化后权重下限 | 约 1.67 MB（仅 int8 卷积权重） | 约 11 KB 级别，另有量化参数 |
| 推理期 VGG/Gram | 不需要 | 不需要 |

外部网络的图核算只计算卷积 MAC，未把 InstanceNorm、激活、搬运和 DDR 访问算进去；因此它的实际硬件负担只会更高。外部卷积量约为 v6 的 149.6 倍，在 15 fps 下约 761 GMAC/s。源代码还包含反射填充、nearest 上采样、InstanceNorm、ReLU 和 tanh，这些都需要硬件实现或近似。

## 按赛题要求审查

| 赛题目标 | 外部博客/仓库证据 | 结论 |
|---|---|---|
| 轻量化风格迁移算法 | 满足算法类别；但网络规模和 MAC 很大 | 算法方向满足，当前 Ti60 部署边界不满足 |
| MIPI CSI-2、RAW/RGB、DDR 双缓冲 | 博客和仓库没有这些硬件系统实现 | 未证明 |
| FPGA 卷积、激活、BN/IN 近似 | 只有 TensorFlow 软件模型，没有 Ti60 RTL/综合证据 | 未满足/未证明 |
| 640×480 实时视频 | eval 可以处理图片，未提供 FPGA 视频链路和 15 fps 实测 | 未证明 |
| HDMI、RISC-V 调度、原画对比、FPS | 未提供 | 未证明 |
| 至少两种动态切换风格 | 配置文件是每种风格独立 checkpoint | 不满足当前多风格切换形式 |
| 参数量小于 500 KB | 仅卷积权重 INT8 也约 1.67 MB | 不满足该高阶目标 |
| PSNR/SSIM 对比 | 页面展示图片和耗时，没有按赛题协议的 PSNR/SSIM | 未证明 |
| 开放授权可直接用于比赛 | 仓库快照根目录未发现 LICENSE/COPYING 文件，博客也未给出权重授权 | 不能直接视为授权清晰 |

赛题没有规定统一的绝对 PSNR/SSIM 合格阈值，因此博客里的“效果好”不能替代同图、同尺度、同参考对象的 PSNR/SSIM 和结构/实时性测试。

## 能否直接建立在它的网络上

在当前 StyleCam 任务边界下，不建议直接替换 v6 图。这样会同时改变通道数、卷积核、残差数量、参数量、MAC、硬件核接口和权重存储，现有 FPGA 推理图及整数对拍全部失效；也不能再声称“只改训练监督”。

可采用的方式是：

1. **作为训练教师或风格参考**：保留 v6 推理图，用该类 Johnson 网络产生高质量教师目标，再蒸馏到 C24/Fc16/dw1/IN 图；训练监督不进入推理图。这也是当前 `algo/teacher.py` 和蒸馏路线的定位。
2. **作为离线算法对照**：对同一批 640×480 留出照片运行外部模型，与 StyleCam FP32/INT8 比较风格强度、主体边缘、PSNR/SSIM 和延迟；只能作为标准网络基线，不能直接作为板端候选。
3. **若另开宽松架构路线**：可以重新实现缩小版普通卷积 FNS，并重新做 Efinity 资源、时序、DDR 和 15 fps 验证；这将是新网络项目，不是 v6 的继承优化。

## 最终判断

这个项目的视觉效果更强，主要来自更大的普通卷积网络、5 个残差块、9×9 首尾卷积和 VGG Gram 风格损失。它与 StyleCam 的**训练思想同源，部署 baseline 不同**。在当前赛题边界下，最稳妥的路线是继续把它当高质量教师/离线对照，优化监督和量化一致性；不要直接把它的网络搬到 Ti60 FPGA。
