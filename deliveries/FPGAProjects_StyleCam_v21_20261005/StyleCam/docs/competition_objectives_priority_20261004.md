# StyleCam 赛题目标与优先级（2026-10-04）

依据工作区中的《全国大学生嵌入式芯片与系统设计竞赛 2026 FPGA 创新设计赛道选题指南（易灵思）》第 4--6 页“赛题一：AI 赋能的实时绘画”，并结合当前 C24/Fc16 StyleCam 实现整理。

## 先区分两类目标

赛题的基础要求决定作品能否被认定为完整的实时视频系统：SC431HAI 的 MIPI CSI-2 采集、RAW 转 RGB、缩放到至少 640×480@30fps、DDR 双缓冲、无丢帧、卷积/激活/BN 或 IN 近似硬件化、HDMI 输出、RISC-V 控制和稳定 15fps 以上。这些是系统验收条件。

赛题的高阶挑战用于拉开作品差距：至少两种风格、不重启动态切换且延迟低于 100ms、1280×720@30fps 或更高、参数量小于 500KB、与标准网络进行 PSNR/SSIM 和推理延迟对比，以及交互展示。PSNR/SSIM 是对比分析维度，题目没有给出统一绝对合格阈值。

## 按优先级排序

### P0：系统可验收、图和接口不越界

这是所有网络优化的前提。网络必须保持输入输出 640×480、RGB 三通道、当前 FPGA 推理图、通道数、层接口和 MAC 预算不变；训练监督可以改变权重，不能引入推理期算子、光流、循环状态或额外帧缓存。

最终系统必须在 Ti60F225I3 上完成 SC431HAI MIPI CSI-2 采集、预处理、DDR ping-pong、风格化和 HDMI 输出。需要记录采集帧、NN 完成帧、显示提交帧的唯一 `frame_id`，证明无重复替代、无丢帧、无 underflow。

当前网络图为 `C=24, Fc=16, n_res=4, block=dw1, IN`，11,028 个参数，1,104 MAC/输入像素，640×480 时 339,148,800 个卷积 MAC。图核对已通过；物理板端、SC431HAI 和整机唯一 `frame_id` 验收仍未完成。

### P1：风格特征必须一眼可辨，并保持主体可识别

这是本项目的首要画质目标，优先于单纯提高 PSNR/SSIM。至少两种风格是赛题高阶挑战的最低目标，本项目目标是三种风格全部稳定可辨：

- 梵高：按区域和结构方向形成连续、成组的长短笔触；天空、道路、水面等大表面要有明显方向性和厚涂明暗；主体轮廓、空间关系和关键物体仍可识别。
- 浮世绘：块内颜色简化、块间边界清楚、深色轮廓可见；不能只把整幅图做成柔和低通或全局调色。量化输出也要保留色块与轮廓。
- 水墨：主体浓墨、背景淡墨/纸白、边缘消散三者分区明显；不能只降低饱和度，也不能把主体和背景都压成同一种灰。

每种风格都要用同图同尺度匿名盲评和结构诊断确认，不能只用颜色统计代替风格判断。视频中还要在运动、曝光改变和风格切换时保持风格可辨，不能出现明显闪烁、抽动或主体漂移。

### P2：FPGA 整数输出必须与训练目标同方向

赛题要求网络真正部署在 FPGA，因此 FP32 预览效果不能作为最终结果。候选必须先经过实际舍入、饱和、IN 参数和系数合同的整数 golden 对拍，再判断风格是否仍然突出；之后才有资格做 RTL 和板端对拍。

当前证据显示这是主要瓶颈：v13 在 24 图上浮世绘块内平坦比例约为 FP32 0.455、整数 0.208；水墨主体浓墨比例约为 FP32 0.387、整数 0.564。后续监督应直接减少这种 FP32/整数分歧，并同时保护主体边缘和视频时序。

### P3：在通过 P1/P2 后尽量提高 PSNR/SSIM

题目要求提交与标准网络的画质（PSNR/SSIM）和延迟对比，但没有规定统一的绝对及格线；因此报告中必须写清参考对象、图像集合、分辨率、量化状态和统计方式，不能把不同教师或不同数据集的数字直接横比。

本项目应采用两层指标：

1. 主指标：同一组留出图、同一 v10 FP32 艺术参考、同一量化合同下，候选整数输出的 PSNR/SSIM。候选首先要求不损失已通过风格门槛的基线质量，再在风格保持不变时提高指标。
2. 辅助指标：对原始照片的 PSNR/SSIM 只用于说明主体和空间保真度，不能把它当成风格质量的唯一标准，因为强风格化必然改变颜色和局部纹理。

工程上可把“整数相对艺术参考约 25 dB、SSIM 约 0.85”作为当前筛选的内部目标线，但它不是赛题官方阈值；若风格明显增强导致指标下降，应以同一协议下的基线差值、盲评和结构可辨性共同裁决。当前 v13 浮世绘整数约 25.04 dB/0.835，仍应继续优化 SSIM 和块状风格；v14 平坦约束最高约 25.56 dB/0.846，但风格块内平坦性仍不足，所以不能单凭指标入选。

### P4：实时性、吞吐和交互响应

基础门槛是 640×480 稳定 15fps 以上；当前项目目标是保留 30fps 摄像头输入链路，并记录完整系统帧率、NN 延迟、DDR 等待和显示帧率。风格动态切换必须不重启、不重新配置 FPGA，至少支持两种风格，切换延迟小于 100ms，切换过程不丢帧。

当前网络核的 150MHz 估算约 26.5fps，不能替代整机实测。必须通过 Efinity 综合、实际 DDR/HDMI/摄像头链路和持续运行测试确认；风格切换时要记录 `frame_id` 和切换起止时间。

### P5：轻量化和 FPGA 资源余量

参数量小于 500KB 是赛题鼓励的高阶目标。当前网络远低于此规模，但系统资源而不是参数量是实际风险：StyleCam 当前综合记录约 172/256 M10K、120/160 DSP、约 37,322/60,800 XLR，外设 IP、DDR、CSI 和 HDMI 加入后资源余量有限。因此不能为了风格增加通道、残差块、额外分支、VGG/Gram 推理模块或后处理。

网络轻量化的排序应是：先保持图和实时性，再在同一图内通过训练监督、权重和量化策略提高效果；只有明确证明资源和帧率仍通过，才考虑任何结构变更。训练期的风格损失、相机增强和时间一致性不计入部署 MAC，但必须确认它们没有改变推理图。

### P6：展示完整度和交互加分

原画/风格画左右对比或按键全屏切换、FPS 叠加、串口/按键切换属于基础展示闭环。挥手切风格、OSD 状态、录制演示视频属于加分项，优先级低于画质、整数一致性和系统稳定性。交互功能不能牺牲帧率、唯一 `frame_id` 或切换延迟。

## 选型决策规则

任何候选必须按 P0 → P1 → P2 → P3 → P4 → P5 → P6 顺序筛选。P1 风格不明显、P2 整数输出不一致、P0/P4 系统边界未验证时，即使 PSNR/SSIM 较高也不能进入部署候选。只有风格盲评、结构可辨性、相机时序、整数对拍、综合资源、整机帧率和切换延迟全部通过，才允许更新 RTL 权重镜像和板端部署文件。
