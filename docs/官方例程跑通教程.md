# Ti60F225 官方例程跑通教程（本机 Efinity 2026.1）

这是一份“照着做”的首次上板流程。目标不是修改代码，而是确认整个链路都正常：

```text
电脑 → USB/JTAG 下载器 → Ti60F225 开发板 → SC431HAI → HDMI 显示器
```

完成标准：LED 例程正常、HDMI 彩条正常、SC431HAI 实时图像稳定显示；随后再重新编译
SC431HAI 工程且时序通过。

| --- | --- | --- |

## 1. 先安装补丁（只做一次）

1. 关闭所有 Efinity、Programmer、Interface Designer 窗口。
2. 按 `Win + R`，输入 `cmd`，按回车，打开“命令提示符”。
3. 在命令提示符中逐行执行：

   ```bat
   call D:\ELS\efinity\2026.1\bin\setup.bat
   cd /d D:\ELS\efinity-2026.1.132.4.5-windows-x64-patch
   run.bat
   ```

4. 出现 `Efinity installation at ... will be modified` 时，输入 `Y` 并按回车。
5. 等待脚本结束；不要在复制文件期间关闭窗口。
6. 重新打开 `D:\ELS\efinity\2026.1\readme.txt` 或 Efinity 的 **Help → About**，确认工具能正常启动。

补丁 `2026.1.132.4.5` 包含 Windows 路径、Programmer/JTAG、MIPI 配置和若干布局布线/GUI
崩溃修复。它不是上次闪退的唯一原因，但应先装好再进行后续调试。

## 2. 正确启动 Efinity

不要双击 `D:\ELS\efinity\2026.1\bin\efinity.exe`。该 exe 依赖启动时设置的
`EFINITY_HOME`、Python 和 Qt 环境变量，直接启动会报：

```text
EFINITY_HOME is not set.
```

正确方式二选一：

1. 使用安装程序创建的 **Efinity 2026.1** 开始菜单/桌面快捷方式；或
2. 打开命令提示符，执行：

   ```bat
   call D:\ELS\efinity\2026.1\bin\setup.bat --run
   ```

看到 Efinity 主窗口即可。第一次可到 **Help → About** 核对版本为 2026.1。

## 3. 接线与上电顺序

1. 开发板断电。
2. 连接 USB/JTAG 下载线到开发板的下载口；连接 HDMI 到显示器；连接 SC431HAI MIPI 排线。
3. 再给开发板上电。MIPI 排线必须依据开发板和摄像头插座的 `Pin 1`/三角标记对齐；方向错误
   时不要上电。
4. Windows “设备管理器”中应出现下载器。若有黄色叹号，使用
   `官方资料\Ti60F225_DemoBoard_v4完整资料包\Ti60F225_DemoBoard_v4\驱动安装及说明`
   中与实际下载器匹配的驱动。

## 4. 第一关：LED/按键例程

目的：只验证供电、JTAG、驱动和最基本的 FPGA 下载。不要跳过。

1. 在 Efinity 中选择 **File → Open Project**。
2. 打开：

   ```text
   C:\Users\lingye\Desktop\FPGA创新赛\官方资料\Ti60F225_DemoBoard_v4完整资料包\Ti60F225_DemoBoard_v4\01_Ti60F225_Key_led_osc_demo\01_Ti60F225_key_demo\LED_8bit_Test.xml
   ```

3. 暂不改任何配置，点击工具栏的 **Compile**（或菜单 **Run → Compile**）。
4. 编译完成后，打开 **Tools → Programmer**，点击刷新/扫描 JTAG。必须能看到 Ti60F225 器件。
5. 在位流文件栏选择工程 `outflow` 中刚生成的 `.hex`；首次调试优先选临时 JTAG/SRAM 模式。
6. 点击 **Start Program**。观察 LED 与按键现象是否符合例程说明。

若此步骤失败，不进入 HDMI：先排查 USB 线、供电、驱动和下载模式。

## 5. 第二关：HDMI 彩条例程

目的：验证 HDMI、显示器、线材、PLL 和板卡输出管脚。

1. 关闭当前工程，打开：

   ```text
   C:\Users\lingye\Desktop\FPGA创新赛\官方资料\Ti60F225_DemoBoard_v4完整资料包\Ti60F225_DemoBoard_v4\03_hdmi_tx_demo\hdmi_tx_demo_v2\led_demo.xml
   ```

2. 点击 **Compile**。每个阶段都应完成：Synthesis、Place & Route、Timing、Bitstream。
3. 在 Programmer 选择生成的 `.hex`，先用 JTAG/SRAM 模式下载。
4. 显示器应锁定信号并显示彩条/测试图。

如果 LED 成功但 HDMI 黑屏，先换 HDMI 线和显示器输入源，检查板卡跳帽；此时不要改动 HDMI
源码、PLL 或约束文件。

## 6. 第三关：SC431HAI → HDMI 官方工程

### 6.1 建立可修改副本

不要直接修改 `官方资料`。复制下面的**整个目录**到本项目的 `工程\video_baseline`：

```text
C:\Users\lingye\Desktop\FPGA创新赛\官方资料\Ti60F225_DemoBoard_v4完整资料包\Ti60F225_DemoBoard_v4\10_Ti60f225_sc431hai2hdmi_demo\Ti60f225_sc431hai2hdmi_v1
```

以后始终从副本打开：

```text
工程\video_baseline\ti60f225_oob.xml
```

### 6.2 先验证厂家给出的位流

1. 打开 `ti60f225_oob.xml`。
2. 打开 **Tools → Programmer**。
3. 选择副本或原始工程中的：

   ```text
   outflow\ti60f225_oob.hex
   ```

4. 调试阶段优先选择临时 JTAG/SRAM 下载；只有确认需要掉电自动运行时，才选择 **SPI Active**。
5. 若选 SPI Active，硬件位流地址是 `0x000000`，然后点击 **Start Program**。
6. 观察 HDMI：应出现 SC431HAI 的实时图像，至少稳定 5 分钟。

例程视频路径为：

```text
SC431HAI I2C 配置 → MIPI CSI-2 RX → Debayer → DDR3 帧缓存 → HDMI TX
```

> 本工程顶层 `readme.txt` 是从较早的通用 `ti60f225_oob` 示例沿用的说明，其中要求写入
> `embedded_sw\\bin\\EFX_HEX_ti60f225_oob.hex`。当前 SC431HAI→HDMI 工程包并不包含
> `embedded_sw` 目录或该固件文件，因此**本例程只下载 `outflow\\ti60f225_oob.hex`**；
> 不要尝试向 `0x380000` 写入不存在的固件。

有彩条但无摄像头画面时，说明 HDMI 可能是正常的；优先排查 MIPI 排线方向、摄像头供电、
摄像头型号与 I2C 配置，绝不能先自己重写 CSI-2 接收器。

### 6.3 再用最新版重新编译

官方工程的历史版本是 2025.2，首次由 2026.1 打开时可能出现“需要更新工程/IP”提示。

1. 只在 `工程\video_baseline` 的副本上确认更新；不要更新原始资料。
2. 先保存工程，再点击 **Run → Compile**。
3. 依次确认四个阶段全部成功。
4. 打开 `outflow\ti60f225_oob.timing.rpt`：必须没有 `FAIL`、未约束主时钟或严重错误。
5. 用新生成的 `outflow\ti60f225_oob.hex` 再次下载并观察视频。

新版 Efinity 对旧工程的第一次全量编译可能较慢；这是正常现象。若 IP 自动升级后编译报错，
保留报错日志和未修改的原工程副本，不要连环点击自动升级。

## 7. 下载模式：日常调试与固化的区别

| 使用场景 | 选择 | 结果 |
| --- | --- | --- |
| 修改 HDL 后快速验证 | JTAG/SRAM/Active（按 Programmer 实际名称） | 断电丢失，安全且适合调试 |
| 演示上电自动运行 | SPI Active，地址 `0x000000` | 写入 Flash，断电仍保留 |
| 例程含 RISC-V 固件 | 另一个软件 hex，按例程指定地址 | 不能覆盖硬件 bitstream |

本赛题的 SC431HAI→HDMI 例程首先只下载硬件 hex。若后续工程包含 Sapphire RISC-V 软件，必须按
该工程 `readme` 指定的 Flash 地址下载，不能猜测或覆盖 `0x000000`。
