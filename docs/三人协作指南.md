# 三人协作

所有人将同一个仓库放在自己的 FPGA 目录，目录结构保持 sc431hai_hdmi 与 FPGAProjects/StyleCam 一致。

- A：摄像头、CSI/DDR/HDMI、约束和 FPGA 顶层。
- B：模型、量化、网络 RTL/权重和整数对拍。
- C：固件、BSP/APB/DDR 地址与整机集成。

main 保持摄像头基线；develop 做集成。工作前拉取最新 develop，再建各自的 fpga/...、ai/...、fw/... 短期分支。不要在共享分支强推。

提交只包含自己的源码和对应验证证据。B 每次更新必须一起交付模型、qparams、生成 RTL/mem/blob 和两个固件头。A/C 的跨接口修改须双方审查。

PR 写清改动、命令、结果及未验证范围。合并后删除功能分支；保留 main/develop。整机确认完成后再将集成成果通过 PR 进入 main。

当前远程清理还因连接写权限 403 未发布；此时以本地整理状态为准，不能把网页上的旧目录当成已完成清理的版本。

## 第一次发布前

本地 develop/main 包含尚未推送的目录整理提交。远程仍是旧目录；在清理提交发布前，不要把网页旧目录覆盖回来，也不要删除本地提交。

写入权限恢复后，在 FPGA 根目录检查 `git status` 和 `git log -1 --oneline`，然后正常推送 main/develop（不使用强推）。确认网页目录已统一，才删除已合并交付分支及旧传感器归档分支。远程清理本轮未执行。

## 每天开始与提交

```powershell
cd C:\Users\lingye\Desktop\FPGA
git fetch origin --prune
git switch develop
git pull --ff-only origin develop
git switch -c ai/具体功能名
# FPGA 负责人使用 fpga/...，固件负责人使用 fw/...
git add FPGAProjects/StyleCam/本次修改的文件
git diff --cached
git commit -m "说明具体修改"
git push -u origin HEAD
```

在 GitHub 创建目标为 develop 的 PR，至少一位队友审核；通过后合并并删除功能分支。下一次工作重新从 develop 建分支。`git add` 指定本次修改文件，避免提交本地数据集、环境和生成产物。

遇到冲突先提交自己的工作，再在功能分支 `git fetch origin`、`git merge origin/develop`，解决冲突后检查并提交；不要用整个目录覆盖队友文件。模型版本切换要同时核对 checkpoint、qparams、RTL/mem/blob 和固件头，使用 `tools/verify_network_merge.py`；包完整性可用 `tools/check_manifest.py`，修改交付包后重新生成清单。

当前 SC 独立摄像头为 1920×1080，网络交付默认 raw3 为 1920×1440；视频尺寸、BSP/APB、DDR 和 board_profile 仍待整机统一。本轮 PC 检查通过不表示已能直接下载上板。


本地 Git 从已验证对象建立，远程基线提交为浅历史边界，旧历史中未用到的文件可能仍需 Git 直连补取；源仓库备份仍在桌面 FPGA创新赛。直连恢复后可 `git fetch --unshallow origin` 补齐历史，再执行正常协作流程。origin 分支记录的是实际远程基线，不包含本地清理提交。
